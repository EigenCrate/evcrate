## Windows harness constraints and safe commands

- Linux qualification can use `node --test tests/advisor-controller/*.test.cjs` and the dedicated fake-backed smoke command above. Do not extrapolate `npm test`, release workflows, or Linux `ps`/symlink behavior to Windows.
- On native Windows, the immediately useful isolated test commands are `node --test tests/advisor-controller/provider-launch-identity.test.cjs` and `node --test tests/advisor-controller/retry-orchestration.test.cjs`; their fixtures are synthetic and backend-free. Run them from the repo root with Node 22.19.0/24.21.0. They do not replace the controller end-to-end tests.
- Before running Windows end-to-end controller/history/state tests, port their fake executable fixture to a Windows-safe package/`.cmd` layout or another already-established no-symlink fixture pattern. The current direct symlink to `.cjs` and chmod assumptions in controller/history/state/mentor/smoke tests are portability traps. Keep the `.cmd` vs native executable distinction: a `.cmd` is a shell launcher, not the advisor's Node script; only fake backend resolution may use it.
- Explicitly build PATH using `path.delimiter` (`;` on Windows), and normalize/remove case-insensitive duplicate `Path`/`PATH` keys before assignment. Set a disposable absolute `HOME` (and matching Windows profile environment where needed), project cwd, temp/state roots, and routing policy; do not inherit the user's actual advisor policy/state. Preserve the existing invalid-explicit-HOME failure behavior; do not add a homedir fallback. Clear advisor recursion markers as current harnesses do.
- Launch test processes from PowerShell with `-NoProfile -NonInteractive`; invoke `node --test ...` directly, not through a PowerShell text pipeline. For any PowerShell-owned checkpoint transport, use explicit UTF-8 bytes/no BOM on redirected standard streams and assert exact UTF-8 stdin/stdout (including non-ASCII JSON) under both Windows PowerShell 5.1 and PowerShell 7. Avoid Read-Host/console prompts and shell-interactive success assumptions. Node child-process pipes should carry the actual protocol payload, not PowerShell's console encoding.
- `windows-2025`/`process.platform === 'win32'` is required. WSL is Linux for Node and skips the Win32-only provider tests; it is not native Windows evidence. Capture `$PSVersionTable`/`$PSVersionTable.PSVersion`, Node `process.platform`, `process.version`, and `process.execPath` for each run.
- Retain the source entrypoint's Node shebang and executable/bin packaging metadata as distribution metadata; do not use either for runtime fallback. Keep `install.sh` shebang/execute-bit and platform guard untouched. No wrapper, `--file` API, entrypoint rename, runtime-denylist gimmick, generic launcher, or backend/retry/OS-internals change belongs in this launch cutover.
