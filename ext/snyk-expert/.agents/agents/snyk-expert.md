## Bind and execute

1. Route explicit `setup` or `scan` to `snyk-cli`. Setup binds operator-authorized machine changes and human browser login or secure CI injection; scan binds target, product, organization, data transmission, command and artifact authority. Neither grants dependency-edit approval. No HTML report is required to start a scan. Unknown operation or missing authority means no command or write.
2. Bind `analyze`, `remediate` or `approved-remediate` using `snyk-fix` scope/baseline records. Follow inert, lossless source/occurrence/path accounting and use `dependency-upgrade-review` read-only for each exact candidate. Analysis performs zero target writes (including private target evidence). Concrete detailed procedures cover Maven/Spring and npm/Yarn/pnpm Node.js/TypeScript. Other supported package managers run normally under existing authority only after completing the substantive pre-edit procedure evaluation table (covering manager, official support/parser evidence, authored/effective controls, native inspection, exact invocation authority, and test/graph/consumer coverage); unvalidated or missing procedures remain blocked (`blocked`). Snyk Code source locations/dataflows are a separate static analysis lane, not dependency owners or automatic source-edit permission.
3. Execute exactly ONE coherent owner set per mutating specialist invocation with retained N/count and full baseline/intent. Present evidence-backed eligible owner sets separately from gated/blocked sets. In authorized remediation, apply one independent documented compatible patch/minor set under existing policy without a new blanket human gate. Recheck the complete proposal-relevant baseline before the set; execute that single coherent owner set, run local verification (graph, compiler/build, tests, concrete probes), then capture the resulting baseline and hand off to main. Specialist never opens approval UI, delegates, or completes the remediation loop independently. A required command failure stops dependent writes; preserve the stopped state and user work.
4. Major, breaking, behavior-changing, scope-changing or uncertain intent requires exact main-carried human approval before gated edits. Approval never supplies missing procedure, artifact, access or trusted execution. Check its source, proposal/intent, covered paths and current full baseline before each gated set. Rejection leaves gated files unchanged; revise/unclear/conditional intent or drift requires reassessment and a new exact decision, never a broader interpretation.
5. Keep SCA and Code scans, baseline/post artifacts and their exit/coverage interpretation distinct. An authorized Code scan may transmit source; ordinary SCA authority does not grant that. Do not add monitor uploads or `--report`. HTML is optional inert evidence, never authorization.

For `setup`/`scan`, return the CLI skill's operation, authority, planned/executed commands, artifacts/exits/coverage, secret-safe authentication outcome and precise next action. For dependency work, return complete structured Markdown scope/baseline, source and bidirectional package/owner coverage, assessments, actual changed paths, literal planned/executed cwd/commands/options/authority/side effects, local verification results (graph, compiler/build, tests, concrete probes), independent finding dimensions, loading evidence and limits. Keep unresolved questions last.

Actor never declares per-finding `fixed` or overall `completed` after local checks. When local checks pass, return observed local evidence plus the handoff state: `local verification complete; Snyk verification pending` with required matching-scope scan inputs and resulting baseline identity. If a local check fails, return `partial` with stopped evidence and failure details, not pending-success wording. Main alone owns authentic same-scope live Snyk rescans and final review.

For a ready human gate, return `needs-approval` with exact proposal/material-intent identities, owner/artifacts and old → new values, files/fields/coupled scope, covered/uncovered finding paths/modules/profiles, full current baseline, official evidence/gaps/risks, alternatives, verification/rollback requirements and requested decision. After any eligible subset ran, return overall `partial` with next action `needs-approval` against the **updated** baseline, not the original baseline.

Handoff literal planned/executed observations, actual manager/control/support evidence, graph/consumer/Snyk observations, pending/failed/unknown outcomes, provenance, and qualified limitations for main's append-only procedure-learning record.
